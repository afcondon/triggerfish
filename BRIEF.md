# Triggerfish — design brief

## What it is
Direct-manipulation UIs for the BEAM-native sequencers (Odonus, Balistes) and
Selene polysignals — the graphical sibling of Calypso (#192), which drives the
same purerl-tidal artifacts via text/eDSL. Stack: **Hylograph + Halogen**.
Output target: a real modular jam over **16 trigger + 24 CV** outs (FH2+expander
/ ES-9 / ES-5+expander).

## The principle: copy the hardware, then transcend it
Andrew already owns the hardware (Grids, René 2, two Euclidean Circles, Ochd +
expander…). So Triggerfish does NOT just replicate a module — it copies it as a
baseline, then does **what the rack makes you patch cables and buy modules for**.
The juicy UI is always where it manipulates an inter-relationship that hardware
hides inside a patch cable (the Hylograph thesis: operate directly on the
elements and their relationships).

- **Odonus** — René/Cartesian grid baseline → the **Fugue-Machine** move: N
  independent playheads over one shared grid, each its own speed/direction/phase.
- **Balistes** — Grids density-map baseline → accents generated by **internal
  Euclideans** (no patch cable).
- **Selene** — one source → many *related* signals; the polysignal *algebra*.

## Aesthetic north star: Swiss rigor × vintage-lab materiality
A tribute to **Hainbach** and old electrical/nuclear-plant test gear — bridged to
Andrew's usual Swiss/light preference through **Dieter Rams' Braun**: Swiss
functionalism rendered as a precision instrument. Reference family: Braun,
Brüel & Kjær, HP, Western Electric, EMS, decade boxes, galvanometers.

- Warm pale **instrument panel** (aged ivory / grey-green), inset edges, a
  maker's **nameplate** (brass strip: "TRIGGERFISH · MODEL ODONUS").
- **Engraved** small-caps section labels (serif, letter-spaced), **tabular mono**
  for numeric values.
- **Skirted pointer knobs** with a 300° arc sweep — drawn, not HTML inputs (the
  knob geometry is ported from `producing-with-your-feet`'s `Donut`; its
  `DonutTree`/`KnobLayer` is the nested-knob = secondary function in the inner
  ring).
- **Pilot lamps** (amber gate / green glide / red skip), unlit = dim dot.
- Restrained palette + brass; the **four live playhead colours are the one
  electric accent** — they earn their brightness by being the thing that moves.
- Build materiality **progressively**: structure first, dress layered. The knobs
  *are* the materiality, so the shared Knob does double duty.

## Layout decisions (current)
- **Quarter each pad**, don't stack a channel strip: every one of the 16 pads is
  a 2×2 — value knob + glide/gate/skip lamps — so the panel reads as an 8×8 of
  controls. (Channel strip is the fallback if quartering reads badly.)
- **Playheads**: a fixed bank of **four** (the Fugue count; per-head mute instead
  of add/remove), each with direction (FWD/BCK/PEND) + speed + interval(transp)
  knobs, sitting under the grid. (Head bank is the next cut.)

## Build state
`Triggerfish.Odonus.Model` (grid brain, ported from `odonus_engine.erl`) +
`Triggerfish.Ui.Knob` (ported Donut) + `Triggerfish.Odonus.Grid` (quartered pads,
drag-to-turn knobs, first Hainbach dress). Runs on local model state; not yet
wired to the real BEAM engine / the 16+24 outs.

## Control idioms (decided in use)
- **Parameter-major small multiples**, not cell-major channel strips: the 16
  cells render as one field per parameter (NOTE knobs; GATE/SKIP/GLIDE/LENGTH),
  every cell carrying the same head-presence ring so playheads sweep all fields.
  Scales by appending a field, never by busying a pad. (Supersedes the quartered
  pad above.)
- **Detented knob** (`KnobView.ticks`): for small discrete ranges (length 1–8,
  ratchet 1–8) the knob draws N tick marks and reads as a rotary selector —
  square footprint of a knob, discreteness of a switch.
- **X-Y selector for intimately-linked pairs**: SPREAD×BIAS is literally the
  Marbles 5×3 chart, so the Marbles control is a single draggable puck in a 2-D
  pad (X = spread, Y = bias), with the live distribution histogram rendered as
  the pad background — you drag *through the diagram*. The rule generalises:
  two parameters that are read together get one 2-D control, not two knobs.

## Parking lot — future panes

- **SuperDirt pane (deferred — after the Balistes/Selene rethink).** A virtual
  module + Triggerfish pane specifically for **SuperDirt**, the software-synth
  end of the trigger-lane spectrum. SuperDirt has a whole vocabulary that has no
  CV/MIDI analogue: named **samples/sounds** (`s`, `n`/sample-index), per-event
  **effects** (gain, pan, shape, crush, coarse, cutoff/resonance, room/size
  reverb, delay/delaytime/delayfeedback, speed, accelerate, legato, sustain,
  unit), and **orbits** (per-orbit effect busses). PolyTrig (Selene) is the
  hardware-bound cousin — gates/notes to ES-9/FH-2/MIDI — and already speaks
  SuperDirt's *naming* idiom (named voices declared in the block + lane-spanning
  `"bd sn cp sn"` routes). The SuperDirt pane would be the full-fat version:
  named samples with per-event parameter columns, addressed by the same
  mini-notation, emitting OSC to SuperDirt rather than gates to hardware. The
  through-line: *one trigger-lane mental model, three emit targets — gate (CV),
  note (MIDI), sample+params (SuperDirt).*
